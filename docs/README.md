# RepoDock engineering documentation

Start here when changing architecture or planning a larger feature.

- `requirements.md` — MVP requirements and acceptance criteria
- `stages.md` — delivery stages and sequencing
- `ux-spec.md` — information architecture and interaction model
- `data-model.md` — persisted domain shape
- `api-contracts.md` — Wails application contract and events
- `extension-playbook.md` — how to add independent modules
- `governance.md` — engineering decision/process rules
- `quality-gates.md` — CI and release quality gates
- `risk-register.md` — initial engineering risk register
- `test-strategy.md` — testing strategy
- `architecture/` — layers, process model, frontend boundaries and extension points
- `security/` — threat model and environment/secret handling
- `operations/` — observability, release and CI/CD
- `adr/` — architecture decision records
- `development/` — coding standards

Claude Code should read `CLAUDE.md` first, then these docs when implementing non-trivial changes.
